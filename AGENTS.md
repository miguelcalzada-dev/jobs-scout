# AGENTS.md

## Project overview

Jobs Scout — AI-powered daily job scraper and matcher. Scrapes Tecnoempleo, InfoJobs, and LinkedIn, matches offers against a user's CV using sentence-transformers embeddings + rule-based scoring, and emails the top 10 every evening via Resend API.

**Stack:** Python 3.12+, FastAPI, SQLite, APScheduler, Jinja2, sentence-transformers, BeautifulSoup4, httpx. Deployed on Railway ($5 plan).

## Commands

```bash
# Install deps (playwright is optional, only for LinkedIn)
pip install -r requirements.txt

# Interactive first-time setup (upload CV, configure preferences)
python3 src/setup.py

# Start the server (daily scrape at 20:00 Europe/Madrid, configurable via DAILY_SEND_HOUR)
python3 src/main.py

# Manual scrape + score + email, then exit
python3 src/main.py --run-now

# Start on a different port
python3 src/main.py --port 8081
```

## Architecture

```
src/
  main.py         FastAPI + APScheduler (entry point, all routes, lifecycle)
  config.py        Settings (pydantic-settings), CVProfile/JobPreferences dataclasses, file I/O
  setup.py         Interactive CLI wizard (CV upload + preference questions)
  cv_parser.py     PDF → CVProfile (LLM via litellm or regex fallback)
  database.py      SQLite via aiosqlite, all CRUD
  scraper.py       BaseScraper, JobOffer dataclass, ScrapeResult
  scrapers/
    tecnoempleo.py  Works (40+ offers/scrape, full descriptions)
    infojobs.py     Works (10-15 offers, limited descriptions — site is React SPA)
    linkedin.py     Needs Playwright Chromium (not installed on Railway, fails gracefully)
  matcher.py        Embedding model + rule-based scoring → 0-100%
  delivery.py       Resend HTTP API for email (NOT SMTP — Railway blocks outbound SMTP)
templates/
  dashboard.html    Full web UI (4 tabs: Ofertas, Mi CV, Preferencias, Historial)
  daily_email.html  Email template
```

## Critical gotchas

### Path handling
`main.py` and `setup.py` have `sys.path.insert(0, ...)` at the top. This is REQUIRED because the app runs as `python3 src/main.py`, not as a module. Without it, `from src.config import ...` will fail with `ModuleNotFoundError`.

### Railway deployment
- **Start command** in `railway.toml` MUST use `--port 8080` literally. Do NOT use `${PORT:-8080}` — Nixpacks does not expand shell variables, and the app will crash with `invalid int value: '${PORT:-8080}'`.
- **Outbound SMTP is blocked** on Railway. Email delivery uses Resend's HTTP API (`https://api.resend.com/emails`). The env var is `RESEND_API_KEY`. The old Gmail SMTP code is dead code on Railway.
- **Volume** at `/app/data` is needed for SQLite persistence across deploys. Without it, the jobs DB is wiped on every deploy.
- **LinkedIn scraper** fails silently on Railway because Playwright Chromium is not installed (too heavy for the $5 plan). The scraper catches `ImportError` and returns zero offers.
- **Python version** is pinned to 3.12 in the Dockerfile. Railway Nixpacks also uses Python 3.12.

### SQLite quirks
- `sqlite3.connect(..., autocommit=True)` is used because Python 3.13 changed the default autocommit behavior. Without it, inserts are silently lost on connection close.
- WAL mode is enabled via PRAGMA for better concurrent read performance.

### Embedding model
- Uses `sentence-transformers/all-MiniLM-L6-v2` (~90MB download on first run, cached by HuggingFace).
- Loaded lazily on first scoring call. Expect ~3-5s delay on first run.
- If the download fails or Railway kills the process during download, scoring falls back to rule-based only.

### Scoring formula (matcher.py)
- `final_score = (cosine_similarity * 50.0) + rule_score`, capped 0-100
- Rule weights (hardcoded, no config): tech match +9 each, title match +15, remote +15, hybrid +10, onsite -40, wrong Spanish city -30
- When `/run` is called via POST, `_rescore_next = True` is set, which forces rescoring of ALL existing jobs (not just new ones).

### InfoJobs scraper
InfoJobs moved to a React SPA. The HTML search results page has limited data. The scraper extracts card text and uses regex for location/modality/tech detection. Job descriptions are the card's visible text, not full job postings. Individual job pages are also client-rendered and cannot be scraped without a browser.

### Environment variables
Set these in Railway (not in `.env`):
- `RESEND_API_KEY` — Resend API key for email
- `EMAIL_TO` — recipient email
- `EMAIL_USER` — sender email (used as Resend `from` address, must match verified domain or `onboarding@resend.dev` in test mode)
- `DAILY_SEND_HOUR`, `DAILY_SEND_MINUTE` — schedule (default 20:00)
- `OPENAI_API_KEY` — optional, enables LLM-based CV parsing (otherwise regex)

## File conventions
- `.env` — gitignored (use `.env.example` as template)
- `config.yaml` — user preferences (gitignored, generated by setup)
- `cv_profile.json` — parsed CV data (gitignored, generated by setup)
- `data/jobs.db` — SQLite database (gitignored)
- `cv/*.pdf` — uploaded CVs (gitignored)
- Templates use standard Jinja2 syntax. The dashboard is a single-page app with inline JS, no build step.
- No migrations framework — schema changes go in `database.py:SCHEMA` via `CREATE TABLE IF NOT EXISTS`.
- Logging format: `%(asctime)s | %(levelname)-7s | %(name)s | %(message)s`
